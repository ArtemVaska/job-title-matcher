# Job Title Matcher

Скрипт для сопоставления исходных наименований должностей с заданным классификатором. Для каждой записи определяется код, наименование по классификатору, степень уверенности и необходимость ручной проверки.

## Подход

Основная сложность - опечатки, сокращения и дополнительная информация в исходных названиях (`Маш. катка`, `Нач. участка АО "МостСтрой"` и т.п.).

Рассматривались несколько вариантов:

- **Fuzzy matching** - простой, но давал слишком высокие оценки при частичном совпадении строк
- **Словари сокращений и регулярные выражения** - хорошо исправляют отдельные случаи, но требуют большого количества правил под конкретные данные
- **TF-IDF по символьным n-граммам** - устойчив к опечаткам и вариантам написания, не требует обучения и внешних сервисов

В результате выбран TF-IDF с символьными n-граммами длиной 2–5 и cosine similarity.

Перед сопоставлением выполняется минимальная нормализация: регистр и Unicode, `ё → е`, удаление пунктуации, лишних пробелов, разрядов и категорий.

Для определения сомнительных результатов используются similarity лучшего кандидата и разница между первым и вторым кандидатами:

- score < `0.35` → `NO_MATCH`
- score < `0.45` → ручная проверка
- margin < `0.05` → ручная проверка

Пороги подобраны эмпирическим путем по `labeled_sample.csv`.

## Качество

На 50 размеченных примерах:

- **Top-1 accuracy:** 90%
- **System accuracy с учётом `NO_MATCH`:** 94% (47/50)
- **8/50** записей требуют ручной проверки

Все 3 оставшиеся ошибки сопоставления были помечены как требующие ручной проверки.

## Установка

Требуется Python 3.11+, тесты проводились на Python 3.14.4

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Для Windows:

```bash
.venv\Scripts\activate
```

## Запуск

```bash
python matcher.py -i data/raw_positions.csv -o results.csv
```

`-o` необязателен, по умолчанию результат сохраняется в `results.csv`.

Для запуска с оценкой на `labeled_sample.csv`:

```bash
python matcher.py -i data/raw_positions.csv --evaluation
```

## Результат

`results.csv` содержит:

`id; исходное наименование; код; наименование по классификатору; уверенность; требует проверки`

Если надёжного соответствия нет, в поле `код` записывается `НЕТ СООТВЕТСТВИЯ`.

## Заключение и улучшения

- Создан MVP, который работает неплохо, но определенно требует доработки
- Тестовая выборка на данный момент довольно маленькая. Для более объективной оценки качества и подбора порогов ее необходимо увеличить
- Есть проблема с похожими наименованиями должностей, состоящими из одного слова - необходимо добавить обработку таких случаев
- При увеличении объёма до 3 млн записей и классификатора до 10 тыс позиций я бы перешел к пакетной обработке данных и поиску ближайших кандидатов без расчета полной матрицы сходства
- Стоит подумать над UI/UX и, возможно упаковкой в docker-контейнер, но возможно это оверкилл. Мне довольно удобно работать из консоли, но обычные пользователи вряд ли оценят, так что стоит придумать минимальный интерфейс с драг-переносом или около того. Также стоит добавить арг-парсинг для классификатора и возможно чего-то еще
- Т.к. это MVP, пока что весь код лежит в одном скрипте, но по-хорошему его стоит декомпозировать на отдельные смысловые блоки
